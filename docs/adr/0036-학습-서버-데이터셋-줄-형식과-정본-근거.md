# 0036. 외부 학습 서버로 보내는 학습 메시지 JSONL(ServerDatasetRow)의 형식과 정본 근거

- 상태: 채택됨 (헤드 E1218 지적, 2026-11-09). [0004](0004-학습은-서버-코드-정본-감싸기.md)·[0030](0030-train은-ssh로-서버-정본을-실행한다.md)의 데이터 쪽을 적는다(대체하지 않음)

## 맥락
`train`이 외부 학습 서버(D78: 학습 구현의 정본은 서버 코드)의 스크립트에 넘기는 데이터는 영역 사이 계약이 아니다. model-lab과 외부 학습 서버의 경계이고, 계약(`boundary-contracts`)은 이 줄 형식을 정하지 않는다(헤드 대장 C03). 그런데 이 형식의 근거가 코드 주석에만 있어, 사용자가 "왜 이 필드인가"를 물으면 답할 문서가 없었다.

## 결정
model-lab이 쓰고 읽는 한 줄의 형식은 영역 스키마 `schemas/ServerDatasetRow.schema.json`이 정본이다(영역 소유, D107). 파일은 `<prefix>_{train,val,test}.jsonl`이고 한 줄은 다음이다.

| 필드 | 형식 | 뜻 |
|---|---|---|
| `scenario_id` | 문자열(1자 이상) | 시나리오 식별. 샘플의 `scenario_id`가 된다 |
| `split` | `train` / `val` / `test` | 계약 샘플의 `TRAIN`/`VALIDATION`/`EVAL`과 `server_row_convert.SERVER_SPLIT`로 대응 |
| `human_review` | 문자열(선택) | 있으면 샘플 `human_review`로 옮긴다 |
| `messages` | 정확히 3개: system, user, assistant 순서 | system은 파일 안에서 한 종류(파일 단위 불변식, 스키마로 표현 못 해 `schemas/README.md` 표 22번) |

`user.content`는 모델 입력을 문자열화한 JSON(LORA_A는 `ActionExtractionInput`, LORA_B는 `ResponseRequest`)이다. 최상위 키는 정렬하고 LORA_A의 `state`는 주어진 순서를 보존하며 한글은 그대로 쓴다(`render_input`). `assistant.content`는 LORA_A면 키를 정렬한 `ActionExtraction` JSON, LORA_B면 응답 문장 그대로(JSON 아님)이다(`render_output`). 입력·출력의 내용은 계약 타입(`ActionExtractionSample`/`ResponseSample`)으로 검증하고 줄 봉투만 영역 스키마가 맡는다.

## 왜 (정본 근거)
- 이 형식은 학습 서버의 학습 스크립트(`train_lora_a.py`, `train_lora_b.py`)가 읽는 messages 형식이다. 학습 목표와 입출력 정본은 데이터셋의 `labels.py`와 데이터 자체이다(워크스페이스 메모리의 정본 지정, D74).
- **확인한 것:** 이 리포의 변환기가 서버 학습 데이터와 글자 단위로 같은 문자열을 만든다는 기록이 `render_input` docstring에 있다("서버 LoRA-A 5,077줄, LoRA-B 5,187줄 전부 일치", 당시 측정이며 이번에 다시 재지 않았다). 변환 왕복은 `tests/test_transform_v2.py`가 시험한다.
- **읽지 못한 것:** 데이터셋 `labels.py`와 서버의 `train_lora_a.py`·`train_lora_b.py` 원본은 이 세션에서 읽지 못했다(워크스페이스 규칙상 이 리포가 읽을 수 있는 이웃 경로가 아니고 서버 접속도 하지 않았다). 따라서 위 표의 필드가 서버 스크립트가 요구하는 전부라고 이번에 확인한 것이 아니다. 스크립트가 읽는 필드의 정본 확인은 열려 있다(헤드 대장 C03).
- 표준: 형식은 채팅 messages(role/content) 관행을 따르며 JSON Lines(한 줄 한 JSON, 줄바꿈 구분)로 쓴다.

## 검토한 대안과 버리는 이유
- 계약(`boundary-contracts`)에 이 줄 형식을 올린다: 영역 사이가 아니라 외부 학습 서버와의 경계이고, 서버가 계약 패키지를 쓰지 않는다. 버린다. 다만 이 형식이 헤드의 C03 후보로 올라 있으므로 헤드가 외부 경계 대장에 둘지 정한다.
- 줄 봉투를 코드로만 검사한다: D117(받아들이는 조건은 스키마에)에 어긋난다. 버린다.

## 결과
얻는 것: 서버로 가는 데이터 형식의 필드·정본·확인 한계가 한 곳에 적힌다. 감수하는 것: 서버 스크립트 원본을 읽기 전까지 이 표는 이 리포가 쓰고 읽는 쪽의 사실이다.

## 되돌리는 조건
서버 스크립트가 다른 필드를 요구하는 것이 확인되면 스키마와 이 표를 고치고 새 ADR로 대체한다. 계약에 올리기로 헤드가 정하면 영역 스키마는 계약으로 위임한다.
