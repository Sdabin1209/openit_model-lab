# 0014. package-adapters의 created_at은 파일 mtime이 아니라 입력에서만 정한다

## 상태
채택 (2026-10-29, 표준성 점검 T22, 헤드 결정표 D106 초안). ADR 0006의 멱등 규칙을 보강한다.

## 맥락
`created_at`은 매니페스트에 들어가 `content_hash`를 바꾼다. 이전 구현은 어댑터·프롬프트 파일의 최신 mtime을 썼다. 같은 내용을 `cp`로 복사하든 `rsync -a`로 복사하든 mtime이 달라지면 같은 어댑터가 다른 `content_hash`를 내고, 이미 게시된 같은 `(package_id, version)`에 `CONFLICT`가 났다(version은 어댑터 해시에서 정해지므로 같다).

## 결정
시각은 `--created-at` 인자(명시 입력)에서만 온다. 주지 않으면 고정 기준 시각 `1970-01-01T00:00:00Z`를 쓴다. 이 값은 "학습 시각을 모른다"는 표지이고 실제 시각이 아니다.

## 왜
- 콘텐츠 주소 지정: 해시는 내용(과 명시 입력)에만 달려야 한다. 재현 가능한 빌드의 원칙도 같다(파일 시스템 메타데이터를 산출물에 넣지 않는다. `SOURCE_DATE_EPOCH` 관행은 시각을 환경이 아닌 명시 입력으로 받는다).
- 이 영역은 서버에서 학습이 끝난 시각을 알 수 없다(학습 기록 `*.train-wrap.json`에는 시각이 없다).

## 검토한 대안과 버리는 이유
- 현재 시각: 실행마다 해시가 달라 멱등이 깨진다.
- 어댑터 해시에서 시각을 만들기: 시각이 아닌 값을 시각처럼 보이게 한다. 거짓 정보다.
- mtime 유지: 위 사고를 되풀이한다.

## 결과
얻는 것: 같은 내용은 어디서 어떻게 복사해도 같은 패키지. 감수하는 것: `--created-at`을 주지 않으면 매니페스트의 `created_at`이 1970년이다. 실제 학습 시각이 필요하면 호출자가 준다. 시험: `tests/test_attach.py::test_same_content_different_mtime_gives_same_content_hash`.

## 되돌리는 조건
학습 기록이 학습 시각을 담게 되면 그 값을 기본값으로 쓰는 새 ADR로 대체한다.
