# 0012. 데이터셋 읽기(I2)는 계약의 HTTP 클라이언트로 한다

- 상태: 채택됨 (헤드 결정 D100). 대체: CR-L004의 "같은 호스트 파일 저장소를 직접 읽는다"(2026-10-15)

## 맥락
I1·I3~I7이 모두 HTTP인데 I2만 같은 호스트의 파일 저장소를 읽었다(`file_dataset_store`). 이웃 저장소 볼륨 공유는 금지다(D49).

## 결정
`inputs.dataset_store`에 `{kind: http, base_url(_env), token_env, timeout}`을 받는다. 클라이언트는 `boundary_contracts.clients.HttpDatasetStore`(HTTP.md `## I2`: `GET /v1/datasets/{id}/versions/{v}`, `.../files/{path}`)이다. `fetch_dataset`은 변하지 않는다(`get_manifest`/`open_file` 후 해시 재확인). `configs/gpu-dev.yaml`은 http로 바꿨다. `factory` 방식과 `file_dataset_store`는 시험 대역과 로컬 개발용으로 남긴다.

## 왜
- D49: 영역 사이는 HTTP. 클라이언트는 계약 패키지에 한 번만 구현한다(D100).
- 토큰은 `*_env`와 `NAME_FILE`로 받는다(D84). registry와 같은 설정 모양을 써 학습 비용이 없다.

## 검토한 대안과 버리는 이유
- 파일 읽기 유지: D49에 어긋나고 이미지가 이웃 구현을 못 넣는다(D100).
- 클라이언트를 이 리포에 구현: 계약과 어긋날 위험, 중복(D100).

## 결과
- 얻는 것: 볼륨 공유 없이 읽는다. 시험 대역 서버(`tests/doubles/dataset_server.py`)로 클라이언트 경로를 시험한다.
- 감수: 네트워크 실패(`UNAVAILABLE`)가 `run-once` 종료 코드 3로 나온다. 실제 `HttpDatasetStore`는 계약 v2.1.0 태그에서 온다. 그 전에는 해당 시험이 건너뛰어진다.
