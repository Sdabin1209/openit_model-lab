# 0015. 설정 YAML은 1.2 코어 스키마로 읽고 중복 키를 거부한다

## 상태
채택 (2026-10-29, 표준성 점검 C2, 헤드 결정표 D106 초안). ADR 0005(설정은 YAML)를 보강한다.

## 맥락
PyYAML은 YAML 1.1로 읽는다. 실행으로 확인한 동작: `off`·`no`가 `False`, `0123`이 8진수 83, 중복 키는 에러 없이 마지막 값이 채택된다. 설정이 `config_hash`와 run 키의 입력이라 조용한 오해석은 다른 run으로 이어진다. 실제로 runbook이 권하는 `disk_policy: off`는 따옴표 없이는 `False`가 되어 스키마가 거부했다(조용히 틀리지는 않았다).

## 결정
`model_lab/config.py`의 `load_yaml12`(PyYAML `SafeLoader` 파생)로 읽는다. 불리언은 `true/True/TRUE/false/False/FALSE`뿐, 정수는 10진·`0o`·`0x`, `null`·`~`·빈 값은 None, 타임스탬프 자동 해석 없음. 중복 키는 `ConfigError`다. `scripts/compare_base_models.py`도 같은 읽기를 쓴다.

## 왜
- 표준: YAML 1.2.2 사양. 10.3.2 코어 스키마가 위 태그 해석을 정하고, 3.2.1.1이 매핑 키의 유일성을 요구한다.
- 시험의 기대값은 이 사양에서 가져왔다(`tests/test_yaml12.py`의 머리말).

## 검토한 대안과 버리는 이유
- ruamel.yaml(1.2를 기본으로 지원, 중복 키 거부 옵션): 표준 구현이라 더 낫다. 새 의존을 잠금 파일에 올리고 두 번째 환경에서 검증하는 일을 하지 않았다(설치를 시도하지 않았다). 설치와 잠금을 확인할 수 있으면 이 로더를 그것으로 바꾸는 새 ADR을 쓴다.
- 스키마에서 타입만 강제: `off`가 `False`로 읽힌 뒤라 원래 의도(문자열)를 복구할 수 없고 중복 키는 못 잡는다.

## 결과
얻는 것: 사양대로의 해석, 중복 키 거부. 감수하는 것: 직접 유지하는 해석 규칙 약 40줄(PyYAML 내부 API `add_implicit_resolver` 사용). 날짜처럼 보이는 값은 문자열이다. 기존 설정은 모두 같은 값으로 읽힌다(전체 시험 통과).

## 되돌리는 조건
ruamel.yaml을 잠그고 검증할 수 있게 되면 대체한다.
