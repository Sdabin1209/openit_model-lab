# 0004. 학습은 학습 서버 코드를 정본으로 두고 감싼다(wrap)

- 상태: 채택됨 (D78, 사용자 결정 2026-10-27; 구현 `model_lab/train_wrap.py`)

## 맥락
학습 서버에는 이미 동작하는 학습 스크립트(`train_lora_a.py`, `train_lora_b.py`)와 데이터셋 v2가 있다. 이 리포에는 파이프라인용 학습기 `trainers/hf.py`가 먼저 만들어져 있었는데, 입력을 `prompt`/`completion` 쌍으로 따로 토큰화하고 채팅 템플릿을 쓰지 않으며 4비트 양자화·gpu-dev 프로파일을 쓴다(`docs/STATUS.md` 12차 갱신). 서버 코드와 결과가 달라진다.

## 결정
학습의 정본은 서버 코드다(D78). 이 영역은 그것을 복사하거나 다시 구현하지 않고 (1) 설정 검증, (2) 명령 조립, (3) 실행, (4) 산출물 확인, (5) 실행 기록만 한다. 서버 스크립트의 인자 이름은 설정 `server.arg_map`에 둔다. `trainers/hf.py`는 비정본 경고를 붙이고 사용처가 있어 삭제하지 않았다.

## 왜
- 사용자 결정(D78): "AI 학습은 학습 서버의 코드가 정본". 학습 담당자의 코드를 이 시스템이 따라 바꾸면 같은 데이터에서 다른 어댑터가 나온다.
- 같은 이유로 데이터셋 v2 형식(D74)을 서버에 맞춘다.
- 얇게 감싸면 서버 코드가 바뀌어도 이 영역의 변경이 인자 이름 한 곳에 모인다.

## 검토한 대안과 버리는 이유
- 서버 학습기를 이 리포에 재구현: 결과가 달라지고 두 벌을 유지해야 한다(D78이 정본을 서버로 정함).
- `trainers/hf.py`를 정본으로 승격: 위처럼 서버와 입력 처리·템플릿이 달라 서버와 같은 어댑터를 만들지 못한다(문서로 확인: STATUS 12차). 삭제하지 않은 이유는 파이프라인(`run`)이 아직 이를 학습기로 쓰기 때문이다. 파이프라인의 `train` 단계는 아직 감싸기에 연결되지 않았다(README, 미정).
- 서버 코드를 가져와 vendor: 서버 코드의 변경을 못 따라가고 라이선스·소유가 불분명하다(추정).

## 결과
얻는 것: 정본과 같은 학습. 감수하는 것: 서버 코드 변경을 자동으로 알 수 없다(ML-12): 설정 `server.script_sha256`과 `train-doctor`의 해시 비교로 완화했다(서버에 접속하지 않는다). 서버 인자 이름은 사람이 코드를 읽어 확인한 값이며 `--help` 실행으로 확인한 것이 아니다(G06). GPU가 필요해 이 PC에서는 실제 학습을 하지 못한다.

## 되돌리는 조건
학습 파이프라인을 비전문가용으로 다시 만들기로 하면(D78 (2), G06) 새 학습기를 정본으로 삼는 새 ADR로 이 결정을 대체한다.
