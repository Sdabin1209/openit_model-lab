# 0001. 모델 레지스트리를 직접 만든다 (I3 + model-registry 서비스)

- 상태: 채택됨 (구현 `model_lab/registry.py`, `model_lab/service/`). 결정 당시의 대안 비교 기록은 없다(아래 "근거 기록 없음" 참고).

## 맥락
모델 패키지(어댑터 두 개 + 매니페스트 + 평가 리포트)를 불변으로 보관하고 release-gate가 읽게 해야 한다. 인터페이스 I3 `ModelRegistry`(게시, 조회, `open_adapter`, 평가 리포트 조회)와 그 HTTP 모양은 헤드가 `boundary-contracts`(`INTERFACES.md`, `HTTP.md` I3 절)에 정했고, 서버는 소유 영역이 구현하도록 D49가 정했다. 환경 제약: gpu-dev는 Docker와 pip이 없고 서버가 꺼질 수 있다(D47).

## 결정
I3를 이 영역이 직접 구현한다. 규칙(스키마·`content_hash`·`adapter_hash`·`serving_config_hash`·시스템 프롬프트 검증, 멱등, CONFLICT)은 한 클래스(`_Core`)에 두고 파일 구현과 메모리 구현이 같은 시험을 통과한다. 서비스(`model-registry`)는 같은 파일 구현을 HTTP로 낼 뿐이다.

## 왜
- **따른 표준**: `boundary-contracts` CONVENTIONS(레코드 불변 D25, 해시는 `boundary_contracts.canonical`로만 계산, 읽는 쪽이 해시를 다시 계산해 `INTEGRITY_ERROR`)와 HTTP.md I3 표. 이 규칙은 외부 제품의 기본 동작이 아니라 이 프로젝트의 계약이다(문서로 확인).
- 계약의 요구가 작다: 패키지 ID/버전 두 단계 조회, 오래된 것부터 `list_versions`, 같은 내용 재게시는 200·다른 내용은 409(HTTP.md I3 표 — 문서로 확인).
- 이웃이 혼자 시험하도록 메모리 구현(가짜 구현)을 함께 배포해야 한다(워크스페이스 규칙). 외부 제품을 쓰면 그 제품의 가짜 구현을 따로 만들어야 한다(추정).

## 검토한 대안과 버리는 이유
**근거 기록 없음**: 결정 당시(2026-10 초) MLflow·Hugging Face Hub·OCI 레지스트리를 비교한 문서나 커밋 메시지를 `docs/`, `head/docs/DECISIONS.md`, `git log`에서 찾지 못했다. 아래는 2026-10-28에 현재 코드와 계약을 놓고 다시 따져 본 것이며, 외부 제품의 사양은 이번에 확인하지 않았다(웹 조회 안 함, 알고 있는 일반 지식).
- MLflow Model Registry: 버전 관리와 UI가 있으나 "같은 버전 다른 내용은 CONFLICT, 같은 내용은 멱등", `ModelPackageManifest` 스키마 검증, `directory_hash`로 읽는 쪽 재검증 같은 계약 규칙을 서버에서 강제하지 않는다(추정). 별도 DB 서버가 필요하다. 계약 규칙을 앞에 덧씌우면 결국 이 래퍼를 만들어야 한다.
- Hugging Face Hub(또는 자체 호스팅): 어댑터 파일 저장에는 맞지만 가용성이 외부(또는 자체 서버)에 달리고 인증 모델이 우리의 역할(읽기/`model-lab` 쓰기) 분리와 다르다(추정). 불변 보장이 태그·커밋 관례에 의존한다.
- OCI 레지스트리(어댑터를 아티팩트로): digest 기반 불변은 잘 맞는다. 그러나 매니페스트 규칙(검증, 목록 순서, 평가 리포트 참조)을 별도로 구현해야 하고, gpu-dev에는 Docker가 없다(D47, 문서로 확인). 서버 안의 로컬 레지스트리는 이미지용으로 deploy가 이미 쓴다(D24).
- 이 영역을 "파일 몇 개"로만 두기: release-gate가 HTTP로만 읽어야 하므로(D49) 서비스가 필요하다.

## 결과
- 얻는 것: 계약 규칙이 한 곳(`_Core`)에 있고, 서버 적합성 시험이 실제 클라이언트로 돈다(`tests/test_service.py`). 외부 서비스 의존 없음.
- 감수하는 것: 인증·동시성·용량·백업·UI를 직접 유지한다(점검 ML-1~3, ML-17). 서명이 없다(ADR 0003).

## 되돌리는 조건
다중 서버/여러 팀이 쓰게 되거나, 버전이 수백 개를 넘어 목록·검색·UI가 필요해지거나, 운영에서 이미 쓰는 아티팩트 저장소(OCI 등)가 정해지면 I3 서버 구현만 교체한다(인터페이스가 계약이라 이웃은 영향 없음). 교체하려면 새 ADR로 이 문서를 대체한다.
