# 0008. 평가 경로 시험은 가짜 모델(오라클)로만 돈다 — 한계

- 상태: 채택됨 (제약에 의한 결정). 한계가 크다.

## 맥락
평가 코드(`evaluate.py`, 지표, 보고서, 회귀)는 서빙과 같은 model-runtime·turn-engine으로 샘플을 돌려 지표를 낸다(브리프 4절). 실제 모델 추론은 GPU가 필요하고 이 개발 PC와 CI에는 GPU가 없다. 모델 성능을 맞추는 것은 이 단계의 목표가 아니고 파이프라인이 끝까지 도는 것이 목표다(D61, D38).

## 결정
시험은 `model_lab/backends/fake.py`의 `oracle_backend`(정답 프롬프트→정답 출력을 그대로 내는 model-runtime `FakeBackend`)로 평가기·보호·보고서 경로를 CPU에서 끝까지 돌린다. `corrupt_every`로 깨진 출력을 섞어 재시도·실패 경로를 지난다. 실제 모델 평가는 `hf` 백엔드(transformers+peft)이고 GPU 호스트에서만 돈다.

## 왜
- 이웃 없이 혼자 시험할 수 있어야 한다는 워크스페이스 규칙(가짜 구현으로 대신).
- 같은 코드 경로(model-runtime `load`/`extract_raw`)를 지나므로 형식·집계·보고서 스키마의 결함은 잡힌다(시험 `tests/test_evaluate_v2.py` 등).

## 검토한 대안과 버리는 이유
- 작은 실제 모델(CPU)로 시험: 느리고 내려받기가 필요하며(디스크 예산, ADR 0007) 결과가 결정적이지 않을 수 있다(추정). 근거 기록 없음(당시 비교 없음).
- 시험 없이 GPU에서만 검증: 반복이 느리고 서버가 꺼질 수 있다(D47).

## 결과와 한계 (확인한 것 / 못 한 것)
- 확인한 것: 지표 계산, 보고서 스키마, 슬라이스, 실패 목록, 재시도 경로가 코드 수준에서 맞게 돈다.
- **확인하지 못한 것**: 가짜 모델은 항상 정답을 내므로 지표 값이 모델 품질을 대표하지 않는다. 제약 디코딩 백엔드는 model-runtime에 아직 없다(CR-L003). `hf` 평가의 실제 성능과 메모리·시간은 이 시험이 보증하지 않는다. 임계치는 정하지 않았다(O11, 사용자 결정).
- 가짜 모델 시험이 통과해도 모델이 좋다는 뜻이 아니다.

## 되돌리는 조건
GPU CI가 생기거나 실제 모델 스모크(gpu-dev의 fixture smoke 설정)를 정기 실행하면 그 결과를 이 ADR의 "확인한 것"에 링크하고 한계 서술을 줄인다.
