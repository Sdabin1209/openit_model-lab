# 0017. 설정의 `module:callable` 팩토리는 허용 목록으로 제한하고 신뢰 경계를 적는다

## 상태
채택 (2026-10-29, 표준성 점검 C6, 헤드 결정표 D106 초안). ADR 0005를 보강한다.

## 맥락
ADR 0005는 "Python 설정 파일은 실행 가능해 임의 코드 위험이 있다"며 YAML을 골랐다. 그런데 `inputs.dataset_store.factory` 등은 `module:callable` 문자열을 import해 호출한다. 설정이 import 가능한 모든 호출 대상을 실행하게 하므로 ADR 0005의 이유와 어긋났다.

## 신뢰 경계 (위협 모델)
- 설정 작성자는 이 시스템의 운영자이며 신뢰 대상이다. 설정은 외부 입력(사용자·환자·네트워크)이 아니다. 데이터셋 저장소·실패 사례 저장소가 돌려주는 내용은 설정을 바꾸지 못한다.
- 막으려는 것은 악의적 운영자가 아니라 실수(오타, 복사한 설정, 잘못된 파일)와 설정 파일 쓰기 권한이 넘어간 경우의 확대 범위다. 쓰기 권한자가 코드도 쓸 수 있다면 이 목록은 방어가 되지 않는다.

## 결정
`model_lab/factories.py`의 `ALLOWED_FACTORIES`(정확한 `module:callable` 문자열의 집합)에 있는 이름만 부른다. 목록 밖이면 import하기 전에 `ConfigError`다. 현재 목록: 계약 HTTP 클라이언트 4종, `model_lab.file_dataset_store:file_dataset_store`, `tests.doubles.dataset_store:from_dir`.

## 왜
- 위협 모델 명시와 최소 권한: 설정이 부를 수 있는 것을 쓰는 것으로 한정한다.
- 허용 목록(allow list)이 차단 목록보다 안전하다는 일반 관행을 따랐다.

## 검토한 대안과 버리는 이유
- 팩토리 방식 제거(종류 필드 `kind`로만 선택): 가장 좁지만 시험 대역과 로컬 개발 경로를 모두 `kind`로 바꿔야 해 이번 범위를 넘는다. 필요하면 새 ADR로 한다.
- 모듈 접두사 허용(`model_lab.*`): 접두사 안의 모든 호출 대상이 열린다.

## 결과
얻는 것: 목록 밖 호출 거부, 시험으로 고정(`tests/test_factory_allowlist.py`: 목록 밖 이름 거부와 import 안 함, 출하된 모든 설정의 팩토리가 목록에 있음). 감수하는 것: 새 팩토리는 코드(목록)와 이 ADR을 고쳐야 한다. 시험 대역 이름이 운영 코드의 목록에 있다(운영 이미지에는 `tests` 패키지가 없어 import에 실패한다).

## 되돌리는 조건
팩토리를 `kind` 선택으로 대체하면 이 ADR을 대체한다.
