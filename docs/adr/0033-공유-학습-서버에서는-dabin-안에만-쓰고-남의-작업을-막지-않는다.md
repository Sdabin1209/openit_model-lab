# 0033. 공유 학습 서버에서는 ~/dabin 안에만 쓰고, 남의 작업을 훼손하지 않는다

- 상태: 채택됨 (사용자 결정 2026-11-03). [0030](0030-train은-ssh로-서버-정본을-실행한다.md), [0031](0031-파이프라인-train-단계는-서버-정본을-부른다.md)의 실행 명령을 바꾼다(대체는 아님)

## 맥락
학습 서버(ssh openit)는 여러 사람이 함께 쓴다. 사용자 결정: 쓰기·수정·삭제는 `~/dabin` 안에서만, 그 밖은 읽기와 `~/dabin` 안으로의 복사만. 모델 캐시는 서버 기본 위치(`~/.cache/huggingface`)를 쓰되 덮어쓰지 않는다. 기준은 "남의 파일·작업을 훼손하지 않는다"이다. 이전 설정은 `server_out_dir`가 `code_dir`(`~/taehyeon`) 아래 상대 경로여서 타인 폴더에 쓰는 문제가 있었다.

## 결정
1. `server.sandbox_root: ~/dabin/openit-model-lab`. 쓰기 경로는 전부 이 아래다: `code/`(정본 스크립트 사본), `tmp/`(TMPDIR), `mpl/`(MPLCONFIGDIR), `uploads/`(`dataset.upload_root`), `runs/...`(`output.server_out_dir`, 파이프라인은 뒤에 `/<run_id>`).
2. 실행 명령 한 줄: `mkdir -p`(위 폴더) → 원본(`~/taehyeon` 또는 `~/myungchan`)을 `code/`로 `cp`(원본은 읽기만) → `cd code` → 사본의 `sha256sum -c` → `exec env TMPDIR=… MPLCONFIGDIR=… python3 <사본> <인자>`. 스크립트가 상대 경로에 무엇을 쓰든 `~/dabin` 안에 머문다.
3. 스크립트 코드(`train_lora_a.py`, `train_lora_b.py`, 2026-11-03 읽음)의 쓰기는 `--out_dir` 아래(adapter, checkpoints, loss_log.json, run_config.json, loss_curve png)와 HF 모델 캐시, matplotlib 설정(스크립트가 matplotlib을 가져옴), 임시 폴더뿐이다. 그래서 `--out_dir`을 `~/dabin` 아래로, `TMPDIR`·`MPLCONFIGDIR`을 `~/dabin` 아래로 돌린다.
4. HF 캐시: `HF_HOME` 등을 덮어쓰지 않는다(`XDG_CACHE_HOME`도, 그것이 HF 기본 위치를 옮기기 때문). 실행 명령에 `force_download`, 캐시 삭제·정리, `--revision` 같은 덮어쓰기 옵션이 없다(시험이 확인). HF 캐시는 내용 해시 이름으로 새 파일만 더한다(허깅페이스 허브 캐시 설계, 이 리포는 구현을 확인하지 않았다).
5. doctor "서버 쓰기 경로": 위 경로가 `~/dabin/` 아래(`..`·빈 구간 없음)가 아니면 FAIL. `train`은 서버에 아무것도 쓰기 전에(업로드·`mkdir` 전에) 같은 검사로 거부한다. `~/dabin` 밖 절대 경로는 같은 폴더를 가리키더라도 거부한다(문자열 규칙이 단순하고 우회가 어렵다).
6. 실행 직전 GPU 점유 검사: `nvidia-smi --query-compute-apps`가 한 줄이라도 내면 `train`은 실행하지 않고 종료 코드 2로 끝난다. 조회 실패도 실행하지 않는다. doctor는 "GPU 점유"로 지금 상태를 보고한다. 남의 작업은 중단하지 않는다.
7. 실행 직전 디스크 검사: 서버의 `~/dabin` 파일시스템과 HF 캐시 파일시스템의 여유가 `2 x (업로드 + 출력 + 모델)` 미만이면 거부한다. 예상 크기는 `output.expected_gb`(필수)이고 근거는 설정 주석에 있다: 업로드 70MB(서버 `du`, 2026-11-03), 출력 이전 학습 한 번 1.2GB(한 번 본 값), 모델 Qwen3-8B bf16 16.4GB(파라미터 수 x 2바이트 계산, **측정 전**, 캐시에 있으면 내려받지 않음). 2배는 사용자 지시이며 측정한 값이 아니다.

## 왜
- 사용자 결정(공유 서버 훼손 금지). 작업 폴더에서 사본을 실행하는 방식은 스크립트 코드를 읽어 쓰기 경로를 모두 알아도 모르는 상대 경로 쓰기까지 막는다.
- 해시 확인을 사본에 하므로 복사 전후에 원본이 바뀌어도 다른 코드가 실행되지 않는다.

## 검토한 대안과 버리는 이유
- 원본 폴더에서 실행하고 `--out_dir`만 `~/dabin`: 스크립트가 상대 경로로 쓰는 것을 막지 못한다(이번에 읽은 코드는 안 쓰지만 바뀔 수 있다).
- `HF_HOME`을 `~/dabin`으로: 사용자가 기본 위치 사용을 허락했고 8B 모델을 중복해 내려받지 않는다.
- GPU 점유 시 대기 후 재시도: 이번 범위 밖(실행하지 않고 알린다). 필요하면 스케줄러(deploy)의 몫.

## 결과
얻는 것: 서버의 `~/dabin` 밖에는 쓰지 않고, 남의 GPU 작업과 디스크를 해치지 않는다. 감수하는 것: (1) GPU 검사와 실행 사이에 다른 사람이 GPU를 잡는 틈은 남는다(검사는 원자적이지 않다). (2) HF 캐시는 서버 기본 위치에 새 파일이 늘어난다(허락됨). (3) 가짜 ssh로만 시험했고 실제 서버에서 `doctor`·실행은 하지 않았다. (4) `~/dabin` 밖의 읽기(원본 스크립트, 데이터셋)는 설정 값 그대로이며 검사하지 않는다.

## 되돌리는 조건
사용자가 허락 범위를 바꾸면(예: 전용 공유 폴더) `SANDBOX_PREFIX`와 이 ADR을 새 ADR로 대체한다.
