# 0003. 모델 패키지 형식과 자기일관성 해시(서명 없음)

- 상태: 채택됨. 서명은 미결정(사용자·헤드 결정 대기).

## 맥락
서빙은 학습·평가한 것과 정확히 같은 어댑터·설정·프롬프트를 써야 한다. 계약 `ModelPackageManifest`가 필드를 정하고 해시 계산은 `boundary_contracts.canonical`만 쓰게 되어 있다(CONVENTIONS 2절, 문서로 확인).

## 결정
역할(LORA_A/B)마다 패키지 하나: 어댑터 디렉터리(`adapter_model.safetensors`, `adapter_config.json`, 시스템 프롬프트 파일), 매니페스트(`adapter_hash = directory_hash`, `serving_config`와 `serving_config_hash`, `system_prompt{path, sha256}`, `lineage`, `eval_report_ref`, `content_hash`), 평가 리포트. 게시 전 모두 재계산해 맞지 않으면 `INTEGRITY_ERROR`/`INVALID_RECORD`. 읽을 때도 `content_hash`와 `adapter_hash`를 다시 계산한다. 내부 부가 정보는 `ext."model-lab"`(비계약 필드)에 둔다.

## 왜
- 표준: RFC 8785(JCS) 정규화 JSON의 SHA-256(CONVENTIONS 2절). 해시를 한 구현에서만 계산해 SDK 사이 불일치를 막는다.
- 시스템 프롬프트를 어댑터와 함께 봉인하는 이유: D75(프롬프트 파일을 패키지가 가진다)와 서빙의 프롬프트 템플릿 불일치를 조용히 넘기지 않기 위해(D80의 취지).
- 해시는 읽는 쪽 SDK도 재검증한다(CONVENTIONS 2절). 저장 뒤 변조를 읽을 때 잡는다.

## 검토한 대안과 버리는 이유
- 서명(키 기반): 게시자 증명이 되지만 키를 누가 어디에 두는지가 정해지지 않았다. **미결정**이라 구현하지 않았다. 해시는 자기일관성일 뿐이라 파일 쓰기 권한자가 매니페스트와 해시를 함께 바꾸면 탐지하지 못한다(점검 ML-6). 제안은 `docs/runbook.md`에 있다.
- 해시만 별도 장부: 같은 신뢰 경계 안이면 이득이 작다(추정).

## 결과
얻는 것: 게시·조회·전달 구간의 우발적 손상과 불일치 탐지, 멱등 판정(같은 content_hash). 감수하는 것: 악의적 쓰기 권한자를 막지 못한다. 게시자 기록(역할·주소·시각)은 별도 파일에 남긴다(서버가 매니페스트를 고칠 수 없으므로).

## 되돌리는 조건
운영에서 레지스트리 쓰기 권한이 영역 밖으로 넓어지거나 외부 감사 요구가 생기면 서명을 도입한다(새 ADR).
