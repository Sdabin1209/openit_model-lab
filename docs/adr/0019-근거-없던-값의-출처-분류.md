# 0019. 근거 기록이 없던 값의 출처 분류 (값은 바꾸지 않는다)

## 상태
채택 (2026-10-29, 표준성 점검 V1~V22, 헤드 결정표 D106 초안 "전 영역" 줄). ADR 0007을 보강한다(0007이 다룬 값은 거기서 가져와 출처 열만 통일했다).

## 맥락
점검에서 timeout·한도·기본값 22건이 "표준 아님 + 근거 없음"이었다. 이 ADR은 값을 바꾸지 않고, 각 값이 측정·표준·제약·가정 중 어디서 왔는지와 측정하지 않았다는 사실을 한 곳에 적는다.

## 결정
출처 분류 기준: **측정** = 이 리포에서 부하·용량·시간을 재서 얻음. **표준** = 이름 있는 문서가 값을 정함. **제약** = 외부 사실(Docker 기본값, 계약, 하드웨어)에서 계산하거나 상한이 정해짐. **가정** = 경험적 추정으로 정함, 근거 없음. **미상** = 정한 이유를 기록에서 찾지 못함.

값이 서버 정본에서 온 경우: `configs/train.yaml`의 하이퍼파라미터는 서버의 실제 학습 `run_config.json`(헤드가 2026-10-27에 읽음)의 값이다. 출처는 학습 담당이고 선정 근거는 이 리포에 없다. 시험이 명령줄을 그 값과 대조한다.

## 왜
D89: 값을 고른 이유를 물으면 근거로 답할 수 있어야 한다. 근거가 없다면 없다고 적는 것이 정직한 기록이다.

## 검토한 대안과 버리는 이유
- 값을 지금 측정해서 바꾸기: 대부분 GPU·실제 어댑터·부하가 필요하다. 이번 범위는 기록만이다(결정표).

## 결과
얻는 것: 어떤 값이 측정된 것이 아니라는 사실의 기록. 감수하는 것: 값 자체는 그대로다. 측정 계획: 진짜 어댑터 크기와 게시 시간은 첫 실제 학습 결과가 생기면, 서비스 한도는 release-gate가 실제 소비를 시작하면 재서 이 표를 갱신한다(측정하지 않은 상태에서 일정은 정하지 않는다).

## 되돌리는 조건
값을 측정하면 해당 줄의 출처를 "측정"으로 바꾸고 새 ADR로 대체한다.
