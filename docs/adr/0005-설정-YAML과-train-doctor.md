# 0005. 설정은 YAML 한 파일, 사전 점검은 train-doctor

- 상태: 채택됨 (D38/D39 파이프라인 원칙, D78)

## 맥락
학습 방법과 하이퍼파라미터는 시행착오의 대상이라 코드가 아니라 설정으로 바꿔야 하고 손으로 명령을 이어 치지 않는다(D38, D39; 브리프 4절). 사용자는 비전문가다(D78). GPU 호스트에서 실패하면 원인 찾기가 비싸다(서버가 꺼질 수 있음, D47).

## 결정
`configs/train.yaml`(A), `train-b.yaml`(B) 한 파일이 서버 경로, 인자 이름 표, 데이터셋, 하이퍼파라미터, 출력 위치를 정한다. 형식은 JSON Schema(`additionalProperties: false`)로 검증하고, 설정 안의 비밀은 시작을 거부한다(D84). `train-doctor`는 실행 전에 서버 스크립트, 데이터셋 파일, GPU, 인자 이름 확인 여부, 파이썬 의존, 기반 모델 캐시, 프로파일, 디스크, 서버 코드 해시를 점검하고 "무엇을 어떻게 고치라"를 말한다. 상태는 OK/WARN/FAIL/HOLE이고 HOLE은 "이 환경에서는 확인할 수 없는 구멍"이다.

## 왜
- YAML: 주석을 달 수 있어 값의 근거를 그 자리에 적을 수 있다(프로젝트 설정 전반이 YAML — 코드로 확인). JSON Schema는 계약 검증과 같은 도구(`jsonschema`)다.
- `additionalProperties: false`: 오타가 조용히 무시되어 기본값으로 학습되는 사고를 막는다(추정, 시험 `test_config_rejections`).
- doctor와 학습 시작 전 점검(`check_ready`)을 분리한 이유: doctor는 모든 문제를 한 번에 보여 주고(비전문가), `check_ready`는 막아야 할 것만 막는다.
- 구멍(HOLE)을 FAIL과 구분한 이유: 이 PC에는 GPU가 없지만 설정은 맞을 수 있다. 확인하지 못한 것을 확인한 것처럼 쓰지 않는다는 워크스페이스 규칙.

## 검토한 대안과 버리는 이유
- 명령줄 인자만: 값이 기록되지 않고 재현이 안 된다. 근거 기록 없음(당시 비교 문서 없음), 위는 D38/D39에서 도출한 판단.
- Python 설정 파일: 실행 가능한 설정은 비밀·임의 코드 위험이 있다(추정).
- TOML/JSON: 근거 기록 없음. YAML을 고른 직접 기록은 찾지 못했다.

## 결과
얻는 것: 같은 설정은 같은 명령(`--dry-run`으로 확인), 실행 기록에 `config_hash`. 감수하는 것: 서버 절대 경로와 타인 홈 경로가 설정에 박혀 있다(ML-12, 프로파일 변수로 분리하는 일은 아직 안 함).

## 되돌리는 조건
서버 코드가 설정 파일 자체를 받게 되면(예: 서버가 YAML을 직접 읽음) 인자 조립 층을 없애고 새 ADR로 대체한다.
