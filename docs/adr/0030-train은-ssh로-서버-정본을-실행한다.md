# 0030. `train`은 ssh로 서버 정본을 해시 고정해 실행하고, 자체 학습기는 폐기 표시한다

- 상태: 채택됨 (G06, D78). [0004](0004-학습은-서버-코드-정본-감싸기.md)를 이어 완성한다(대체하지 않음)

## 맥락
[0004](0004-학습은-서버-코드-정본-감싸기.md)는 학습 정본을 서버 코드로 정하고 감싸기를 만들었으나 (1) 감싸기는 서버 안에서만 돌았고 이 컴퓨터에서는 `--dry-run`뿐이었다, (2) 코드 해시를 설정에 적지 않으면 경고(WARN)만 나와 확인하지 않은 코드로 학습할 수 있었다, (3) `--out_dir`에 어댑터 폴더를 그대로 넘겼는데 서버 스크립트는 어댑터를 `<out_dir>/adapter/`에 저장한다(2026-11-03에 `ssh openit cat`으로 읽은 `train_lora_a.py` 143행 `model.save_pretrained(OUT / "adapter")`). 자체 학습기(`components/lora_train_hf.py`)는 서버와 다른 어댑터를 만든다.

## 결정
1. `model-lab train` 한 명령이 `server.ssh.host`(~/.ssh/config 이름)로 서버의 정본 스크립트를 그대로 실행한다. 스크립트는 복사·수정하지 않는다. 인자는 `configs/train*.yaml`의 `arg_map`·`hyperparams`에서만 온다. `server.ssh`를 지우면 이전처럼 서버 안에서 직접 돈다.
2. 실행 명령은 `cd <code_dir> && echo '<sha> <스크립트>' | sha256sum -c --quiet - && exec <python> <스크립트> <인자>` 한 줄이다. 서버에서 해시가 맞을 때만 실행된다.
3. 실행 전 점검(`train-doctor`, `train`의 `check_ready`): 서버 접속과 스크립트 읽기, 데이터 파일 3개, GPU(`nvidia-smi -L`), 스크립트 sha256 == 설정 `server.script_sha256`, `arg_map`이 스크립트의 `add_argument`에 선언되어 있는지, 파이썬 의존. **해시가 비어 있으면 FAIL**이고 현재 해시와 채우는 방법(`ssh <호스트> cat/sha256sum`)을 출력하며 `train`은 실행을 거부한다. 해시가 다르면 거부한다. 원격에서 GPU가 없다는 답은 구멍(HOLE)이 아니라 FAIL이다(서버를 직접 물었다).
4. 학습이 끝나면 `<server_out_dir>/adapter/`를 `rsync -a`(서버 쪽은 읽기)로 `output.adapter_dir`에 가져와 기존 어댑터 점검과 학습 기록(`*.train-wrap.json`)을 쓴다. 그 폴더와 기록이 `package-adapters`의 입력이다(기존 package 단계는 바꾸지 않았다). 서버 쪽 출력은 서버의 기존 기록(`runs/a_8b_v2` 등)과 겹치지 않는 새 이름(`runs/ml_*`)을 쓴다.
5. 자체 학습기 `lora_train_hf`는 폐기 표시한다(모듈 머리말, 파이프라인의 경고를 `DeprecationWarning`으로). 삭제하지 않는다.

## 왜
- 사용자 결정 D78(학습 정본 = 서버 코드). 해시 고정은 "정본이 바뀐 줄 모르고 다른 어댑터를 만드는" 위험(ML-12)을 닫는 가장 싼 방법이다.
- 해시 확인을 실행과 같은 ssh 명령 안에 넣은 이유: 점검과 실행이 다른 연결이면 그 사이 파일이 바뀔 수 있다. `sha256sum -c`는 coreutils 표준이다.
- ssh 옵션 `BatchMode=yes`, `ConnectTimeout=10`: 비밀번호 질문으로 멈추지 않고 서버가 꺼져 있으면 빨리 실패하게 한다(워크스페이스 gpu-dev 규칙의 값을 따름). `ServerAliveInterval=60`: 긴 학습 중 유휴 연결 끊김을 줄이는 ssh의 표준 옵션이며 **60초는 측정하지 않은 관례값**이다.
- `rsync -a`로 가져오기: 이 리포 브리프의 파일 이동 방식(GPU 호스트 절)과 같고 중단 후 재실행해도 안전(멱등)하다.
- 인용은 `shlex.quote`, 앞의 `~/`만 `"$HOME"`으로 풀어 공백이 든 경로(B 데이터 경로)가 인자 하나로 간다. 해시와 스크립트 이름은 스키마(`^[0-9a-f]{64}$`, 파일 이름 패턴)가 제한해 명령 주입을 막는다.

## 검토한 대안과 버리는 이유
- 서버에서 `nohup`으로 분리 실행하고 로그를 폴링: ssh 끊김에 강하지만 폴링·재접속 설계가 따로 필요하고 이번 범위(한 명령) 밖이다. 끊기면 오류 메시지로 서버 학습이 계속될 수 있음을 알린다. 장시간 학습에서 끊김이 실제로 생기면 이 대안으로 새 ADR을 쓴다(측정하지 않음).
- 서버에 이 리포를 설치해 서버 안에서 실행: 서버에 의존 설치·코드 배포가 필요하고 서버 코드 소유 영역을 건드린다.
- 해시 없으면 경고만(이전 동작): 확인하지 않은 코드로 학습할 수 있어 버린다.
- 자체 학습기 삭제: 파이프라인 `train` 단계와 평가 백엔드가 아직 사용한다. 파이프라인 `train` 단계의 연결은 [0031](0031-파이프라인-train-단계는-서버-정본을-부른다.md)에서 했다.

## 결과
얻는 것: 한 명령으로 서버 정본 학습 + 어댑터 회수 + 기록. 코드 변경은 해시 갱신 없이는 실행되지 않는다. 감수하는 것: 서버 코드가 바뀔 때마다 사람이 읽고 해시를 갱신해야 한다. 가짜 ssh로만 시험했다(명령 모양, 해시 거부, doctor 출력). 진짜 서버·진짜 학습·`--help` 실행은 확인하지 않았다 [구멍: GPU]. 원격 모드의 디스크 점검은 이 컴퓨터(가져올 위치)만 본다.

## 되돌리는 조건
학습 서버 코드가 이 리포의 소유가 되거나 서버가 설정 파일을 직접 받게 되면, 또는 ssh 끊김이 실제로 학습을 망치면 새 ADR로 대체한다.
